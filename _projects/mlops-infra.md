**틸다, 2025.04 – 2026.07, 1인 프로젝트**

## 문제 정의

태양광 설치 장소마다 서로 다른 모델을 사용하고, 학습된 모델이 주기적으로 추가되거나 한 차례 예측 후 교체되는 환경을 위한 MLOps 인프라를 구축했습니다. 모델 학습과 등록을 자동화하고, 2개 예측 Node 중 1개에 장애가 발생하는 조건에서 예측 요청 유실을 개선하는 것이 목표였습니다.

## 접근 방법

Pod 메모리를 효율적으로 사용하기 위해 모델마다 별도의 Serving Pod를 고정하지 않고, 요청된 모델을 가용한 예측 Pod에 동적으로 Load하고 Routing하는 **ModelMesh**를 사용했습니다. Cron을 통해 온프레미스에서 학습한 모델을 **MLflow**에 저장한 뒤 ModelMesh에 등록해 학습과 Serving 과정을 연결했습니다.

ModelMesh는 한 번 Load한 모델을 여러 예측 요청에서 재사용하는 Caching을 전제로 동작합니다. 그러나 모델이 한 차례 예측 후 교체되는 환경에서는 이 방식이 적합하지 않았습니다. 이에 ModelMesh의 Caching 설정을 워크로드에 맞게 수정하고, 모델을 동적으로 Load하는 동안 들어오는 요청을 보관할 수 있도록 **Queue Proxy**를 구현했습니다.

## 장애 대응 개선

Node 2개 중 1개를 삭제하면서 300건의 예측을 요청한 초기 장애 테스트에서는 실행 중이던 요청 2건이 유실됐습니다. 대기 중인 요청은 정상 Node로 Load Balancing됐지만, 장애가 발생한 Node에서 실행 중이던 요청은 복구되지 않았습니다.

이를 보완하기 위해 Queue Proxy에 장애 발생 0.5초 후 한 차례 재시도하는 로직을 추가했습니다.

## 결과

재시험에서는 300건에 대해 요청 유실이 발생하지 않았습니다 (**2건 → 0건**).
